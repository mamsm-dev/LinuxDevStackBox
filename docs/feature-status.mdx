## v0.1.19 logs, cache and packaging

Shared log viewer supports Clear view, verified GZIP archives, export, typed delete confirmation, and opt-in rotation settings; Logs workspace adds Archives & rotation. Workspace cache reduces blank reloads on Projects, Databases, and Users. The package ships a policy-staged phpMyAdmin payload with pmahomme only. Live Apache/MySQL rotation while services run remains future work.

## v0.1.18 database workspace

Three-tab workspace for local MySQL: database list and details, user accounts with database permissions, and Import & Export (SQL, GZIP, single-SQL ZIP and LinuxDevStackBox ZIP packages), saved backups with integrity checks, activity history, and full-server backup. Ordinary ZIP imports require exactly one SQL file at the archive root; LinuxDevStackBox packages restore their recorded database names. Copy/migrate, remote transfer, and account rename remain deferred.

## v0.1.17 Apache compatibility

The explicit directory-override baseline prevents ancestor .htaccess failures while retaining document-root rewrite rules. Existing configurations receive an additive, backed-up, syntax-checked migration. Explicit custom policies remain effective. The log viewer shows the file path, and project diagnostics warn when the selected folder contains public/index.php. See [Projects](getting-started/projects) and the release validation report for verified scope.

## Recent releases

v0.1.16 added streamed SQL restore, streamed backups and preservation-aware import-limit migration. v0.1.15 corrected updater download progress.

## PHP runtime

PHP is the single system runtime from the distribution (minimum supported version 8.2). There is no bundled PHP, no version download and no version switching; security patches arrive through normal distribution updates. The app reports the actual runtime version from `php --version` rather than treating a branch label as a complete version.

## Diagnostics

Project details can read Apache and runtime-specific PHP errors. Configuration changes preserve recovery snapshots and reject unrecorded generated hosts before site edits. Logs are shared, and the saved PHP setting is not live runtime verification.
