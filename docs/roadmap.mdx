# LinuxDevStackBox - Official Roadmap

**The single source of truth for what we are building and in what order.**  
Feature requests and discussions: [GitHub Discussions](https://github.com/mamsm-dev/LinuxDevStackBox/discussions)

---

## Product Vision

LinuxDevStackBox will become the **best modern PHP local development stack for Linux**.

It is NOT a universal developer infrastructure platform. Scope is intentionally limited.

**Core Stack (from distribution packages, not bundled):**

- Apache HTTP Server
- PHP (the single system runtime, minimum 8.2)
- MySQL/MariaDB (distribution server, run from the user's data dir)
- phpMyAdmin (bundled with the app)

No Docker, no Redis, no PostgreSQL, no Node runtime manager - not in v1.

**Packaging Philosophy:**

> Install the package + the distribution stack → Start → Works.

The app package is small because Apache, MariaDB/MySQL and PHP come from your distribution. If a required binary is missing, the app refuses to start the service and prints the exact install command for your package family:

- Arch: `sudo pacman -S apache mariadb php php-cgi`
- Debian/Ubuntu: `sudo apt install apache2 mariadb-server php php-cgi`
- Fedora: `sudo dnf install httpd mariadb-server php php-cgi`

**What is packaged vs provided by the distribution:**

| Component           | Strategy      | Notes                                                  |
| ------------------- | ------------- | ------------------------------------------------------ |
| Apache              | Distro package | `apache` (Arch), `apache2` (Debian), `httpd` (Fedora)  |
| PHP + php-cgi       | Distro package | Single system runtime, minimum 8.2; no version switching |
| MySQL/MariaDB       | Distro package | Data lives in the user's data dir, so updates never touch databases |
| phpMyAdmin          | Packaged      | Writable copy in the app's data dir, served at `/phpmyadmin` |
| Default configs     | Generated     | Required for first launch                              |
| Sample `www/` page  | Packaged      | Confirms stack works immediately                       |
| Node.js support     | Future module | Not in v1                                              |
| Redis               | Future module | Not in v1                                              |
| PostgreSQL          | Future module | Not in v1                                              |

Because the stack comes from the distribution, the app package stays small. Do not sacrifice reliability or UX to reduce package size.

## Current documentation baseline: v0.1.22

**v0.1.22** improves **UI contrast** and adds a **stable-read command cache** for PHP and configuration tabs. **v0.1.21** improves **MySQL import diagnostics** and fixes the About **Update Available** button label. **v0.1.20** improves **log UX**, **virtual-host error handling**, **bulk service controls**, and **plain ZIP SQL import** in the database workspace. **v0.1.19** adds **log management** (clear view, archives, safe delete, rotation settings) and a **workspace cache** for faster navigation. **v0.1.18** adds the **database workspace** (Databases, Users, Import & Export) with details, SQL/GZIP/ZIP transfer, saved backups, activity history, and database-level permissions. **v0.1.17** adds the Apache ancestor `.htaccess` baseline with an additive migration, log paths and document-root diagnostics. Published on 23 October 2026; see the release validation report for installed-site test coverage. **v0.1.16** streams large `.sql` restores from disk, migrates PHP/phpMyAdmin import limits safely, and streams mysqldump backups without loading dumps into RAM. **v0.1.15** fixes update-check download progress. **v0.1.13** adds project error-log access and safeguards for configuration updates. **v0.1.12** introduced **project workspaces** (connect folders outside `www`) and **trusted local HTTPS** with a per-user certificate authority. ## Next after v0.1.22

Planned in this order for upcoming releases:

1. **Composer** - bundled or one-click install, integrated with project folders and PHP runtimes.
2. **Git** - detect repos, basic status, and open terminal in project context (no full Git hosting).
3. **Nginx** - optional reverse proxy / alternate web server module alongside Apache (not replacing the default stack in v1).

**Note:** This feature was completed on the Windows codebase, which downloaded extra PHP versions from windows.php.net. These are explicitly out of scope for the current product:

- Docker / container management
- Plugin marketplace
- Cloud sync
- Mobile development tools
**The following are deferred to future optional modules (not in the v1 core package, but planned or possible later):**

- **Nginx** - see **Next after v0.1.22**; Apache remains the bundled default
- Redis (future optional module)
- PostgreSQL (future optional module)
- Node.js runtime manager (future optional module)
- Python / Ruby runtimes (future optional module)

**Rationale:** These would fragment effort and dilute the core PHP stack focus. The goal is to be the best PHP stack first. Modular extensions can be added after v1.0 is stable and trusted.

## MySQL / MariaDB (Decided)

LinuxDevStackBox uses the **MySQL-compatible server from your distribution** (MariaDB or MySQL).

- Runs from the user's data dir with a generated `my.cnf`; data lives in `~/.local/share/linuxdevstackbox/mysql-data`, so package updates never touch databases
- Works with both MariaDB (initialized with `mariadb-install-db`) and MySQL (initialized with `mysqld --initialize-insecure`)
- Binds `127.0.0.1` on port 3306 with its socket inside the data dir
- Tauri command names: `start_mysql`, `stop_mysql`, `mysql_status`, `mysql_version`, etc.
- Works out of the box with phpMyAdmin, Laravel, WordPress, and other standard PHP tooling
