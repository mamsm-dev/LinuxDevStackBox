# Terminal tabs and shells

Open **Terminal** to use local shell tabs. Commands run on your computer with your user's privileges; the terminal is not a sandbox.

## Open and use a session

1. Choose Shell, PHP Interactive or MySQL CLI from the tab controls. Shell spawns your login shell in a PTY.
2. Inspect the prompt and current directory before running project commands.
3. Change to the intended project folder explicitly. A project hostname does not automatically change the shell's directory.
4. In a Shell tab, run a harmless version check such as `php -v` when verifying the CLI runtime. PHP Interactive opens `php -a` and expects PHP input instead of shell commands.
5. Switch tabs to keep sessions separate. The app allows ten tabs; close an unused session if a new tab cannot be opened. Closing the last tab creates a new default Shell tab.

Navigating away from Terminal keeps its mounted sessions available while the app is running. This is not session restoration after an app restart.

## Clear versus close

**Clear** clears the active terminal's scrollback display. It does not undo commands or remove files. Closing a tab or using **Kill** ends its session; stop or save any work in that shell first.

## PHP and MySQL

Terminals use the system PHP, the same runtime that serves your websites. Reopen sessions after upgrading the distribution `php` package.

The MySQL CLI is a separate client session. Authentication can fail even when the app's database list works; supply the credentials required by that client rather than assuming the app's stored credential is injected into every shell. Do not put passwords in screenshots or command history.

## Session failures

Read the launch error, check the executable and working directory, then create a new tab. If PHP is missing, install the distribution PHP packages - the app prints the install command for your family; see [PHP](php). If only a project command fails, inspect that application's dependencies and environment; LinuxDevStackBox does not install Laravel/WordPress dependencies when connecting a folder.


## PHP in external terminals

The `php` command on your `PATH` is the distribution's PHP runtime; LinuxDevStackBox does not add its own PHP binary to `PATH`. Open a new terminal after installing or upgrading PHP; restart an already-open IDE or terminal emulator if it still has the old environment.

Run `which php`, `php -v`, and `php --ini` to check resolution. The app's generated configuration lives at `~/.config/linuxdevstackbox/php.ini` and drives the managed stack (Apache/php-cgi); an external CLI uses your distribution's PHP configuration unless you point it at that file explicitly with `-c` or `PHPRC`.

PHP's `-n`, `-c` and `-d` options remain available for explicit overrides. Extensions come from the distribution PHP extension directory.
