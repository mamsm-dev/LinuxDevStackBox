# PHP runtime and extensions

Open **Services → PHP**. The Overview, Extensions and php.ini tabs cover different aspects of the runtime. LinuxDevStackBox uses the single PHP runtime installed by your distribution (minimum supported version 8.2). There is no bundled PHP, no version download, and no version switching. The app displays the actual version reported by `php --version` rather than treating a branch label as a complete version.

## Upgrading PHP

Upgrading PHP means upgrading your distribution's `php` package:

1. Update the system as usual (for example `sudo pacman -Syu`, `sudo apt upgrade` or `sudo dnf upgrade`).
2. Stop Apache before replacing the runtime files, and close terminal sessions using PHP.
3. Start Apache again and verify the affected websites.
4. Use **Refresh** in the app so it re-reads the new version.

Extensions come from the distribution's PHP extension directory; install additional extension packages with your package manager if a project needs one.

## Extensions

1. Open **Extensions** and check the default runtime.
2. Filter the list to find the extension.
3. Toggle a switchable module; built-in entries cannot be enabled or disabled in the same way.
4. Restart Apache and verify that the application can load the module.

The extension UI targets the generated global `php.ini`, not every configuration variant. If a framework still reports a missing extension, verify the runtime serving that website and its loaded configuration before changing more files.

The generated profile enables common extensions such as `mysqli`, `pdo_mysql`, `pdo_sqlite`, `sqlite3`, `mbstring`, `openssl`, `curl`, `gd`, `zip`, `intl`, `fileinfo`, `exif`, `sockets` and `sodium` when the corresponding modules are present in the distribution's PHP extension directory. Existing profiles retain explicit extension choices. Optional third-party modules such as Imagick are not preconfigured; GD supplies image support. Individual plugins and applications may require additional modules - install their distro packages and enable them here.

These defaults follow the [Laravel requirements](https://laravel.com/docs/12.x/deployment#server-requirements) and [WordPress server guidance](https://make.wordpress.org/hosting/handbook/server-environment/). Check each project's dependency requirements as well as your distribution's PHP build.

## Temporary files

Missing or empty `sys_temp_dir` and `upload_tmp_dir` are initialized to the user's LinuxDevStackBox `tmp` directory. The directory is created per user; no developer username is baked into the package. The fix applies to new profiles and older configurations. Nonempty custom paths are preserved: ensure those paths exist and are writable. Restart Apache after configuration changes; existing PHP processes retain their old settings.

## php.ini and information

The per-user `php.ini` is generated at `~/.config/linuxdevstackbox/php.ini`. Use the **php.ini** tab for the user copy and [configuration history](configuration-editor). Updates preserve user settings within the documented migration limits; this is not a promise that every directive is untouched. The runtime information action helps identify configuration and extensions; avoid publishing its complete output because it can expose local paths and environment details.

## Recover from failure

If the app reports PHP as missing, install the distribution packages - the app prints the install command for your family (Arch: `sudo pacman -S php php-cgi`; Debian/Ubuntu: `sudo apt install php php-cgi`; Fedora: `sudo dnf install php php-cgi`). If a website reports a missing module, install the matching distro extension package, enable it in **Extensions** and restart Apache. If PHP behaves oddly after a system upgrade, compare the loaded configuration with your saved php.ini history before editing anything.

## Refreshing PHP information

Overview, Extensions and php.ini share session-cached PHP information for up to five minutes. Navigating between tabs does not repeat runtime queries while that result is fresh. Installing or upgrading PHP invalidates related information; changing extensions invalidates the extension list and configuration reads. Use **Refresh** to check immediately after changing PHP outside LinuxDevStackBox. Failed checks have a short retry window rather than a long-lived cache.

Configuration reads are reused for up to one minute across visits; **Reload** reads from disk immediately. Unsaved drafts remain separate from the read cache. Save and Restore invalidate the affected configuration and backup list.
