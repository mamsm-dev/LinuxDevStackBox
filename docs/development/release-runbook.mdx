# Release runbook

Run from the repository root on Linux. GitHub Actions performs the package builds and the release publication once a version tag is pushed; this runbook covers preparing the release, triggering it, verifying it, and building packages locally.

## 1. Preflight

```bash
git status                          # clean tree
node scripts/verify-packaging-metadata.mjs
npm ci
npm run check
npm run test:packaging
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

The metadata check confirms package.json, src-tauri/tauri.conf.json, src-tauri/Cargo.toml, src-tauri/Cargo.lock, packaging/arch/PKGBUILD, packaging/debian/changelog and packaging/fedora/linuxdevstackbox.spec all declare the same version. Bump all of them in one commit when releasing (the Debian revision suffix `-1` stays out of the comparison).

## 2. Trigger the automated release

```bash
git tag v1.0.0
git push origin v1.0.0
```

Pushing the tag triggers the `Release` workflow, which validates the run context and the tag against the manifests, builds all packages in their native environments, and publishes a GitHub Release containing:

- `linuxdevstackbox-<version>-1-x86_64.pkg.tar.zst` (Arch)
- `linuxdevstackbox_<version>-1_amd64.deb` (Debian)
- `linuxdevstackbox-<version>-1.fc<release>.x86_64.rpm` (Fedora)
- `LinuxDevStackBox_<version>_amd64.AppImage` (portable bundle)
- `SHA256SUMS` (checksums of the four assets)

Watch the run under the repository's **Actions** tab. If any build fails, no release is published. Release notes are generated by GitHub from the tag's commits; the repository changelog is not edited automatically. `latest.json` for the in-app check-only updater is attached to the release separately if the update flow needs it (see the release process page).

Important: a release is created ONLY by pushing a `v*` tag. Manual `Build Linux packages` runs (workflow_dispatch) upload artifacts for testing and never publish - the run output states this explicitly.

## 3. Verify the published release

```bash
gh release view v1.0.0
gh release download v1.0.0 --dir /tmp/release-check
cd /tmp/release-check
sha256sum -c SHA256SUMS
```

Every checksum must match. Then, where you have the target distributions available, install each package and run the qualification gates from [Release process](./release-process). Record results in docs/RELEASE-VALIDATION.md; the automated pipeline validates build success and package metadata only.

## 4. Build packages locally (optional)

Each package is built the same way CI builds it:

```bash
# Arch Linux
git archive --prefix=linuxdevstackbox/ \
  -o packaging/arch/linuxdevstackbox-<version>.tar.gz HEAD
cd packaging/arch && makepkg -f

# Debian (Ubuntu/Debian host with debhelper, node, cargo and the WebKitGTK
# development packages installed)
cp -a packaging/debian ./debian
dpkg-buildpackage -us -uc -b      # .deb appears in the parent directory

# Fedora (Fedora host or container with the spec's BuildRequires installed)
git archive --prefix=linuxdevstackbox-<version>/ \
  -o linuxdevstackbox-<version>.tar.gz HEAD
rpmbuild -bb --define "_sourcedir $PWD" --define "_rpmdir $PWD/dist" \
  packaging/fedora/linuxdevstackbox.spec
```

The `.deb` and `.rpm` produced by `npx tauri build --bundles deb rpm` (Tauri's own bundler) remain a development convenience for quick local installs; release packages come from `packaging/debian` and `packaging/fedora` so the distributions' native tooling stays the source of truth.

## 5. Troubleshooting

- **"Release tag X disagrees with application version Y"** — one manifest was not bumped. Fix the file listed by `scripts/verify-packaging-metadata.mjs` and re-tag (tags are immutable; move or delete the tag deliberately).
- **Arch job fails at `pacman -Syu`** — usually a transient mirror error; re-run the job.
- **Debian job fails in `dpkg-buildpackage`** — check the failing step: `npm ci` (lockfile out of sync), `cargo build --frozen` (Cargo.lock stale), or a missing build dependency in `packaging/debian/control`'s `Build-Depends` that must be added to the job's apt install list as well.
- **Fedora job fails in `rpmbuild`** — a missing `BuildRequires` entry in `packaging/fedora/linuxdevstackbox.spec` or a Rust toolchain too old for the current `Cargo.toml` dependency set.
- **Release job reports a version mismatch** — the built package file name does not contain the tagged version; a manifest was bumped after the tag was cut. Re-tag the corrected commit.
- **Wrong architecture** — all three packages are x86_64-only (`ExclusiveArch`/`Architecture: amd64`/`arch=('x86_64')`); aarch64 support is a deliberate future change requiring a build matrix.
