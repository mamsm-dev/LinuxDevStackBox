# v0.1.22 release runbook

Run from the app repository root on Linux. Source preparation is not proof of a published or package-qualified release. Follow [Release process](./release-process) for acceptance gates.

## Preflight

```bash
npm ci
npm run check
npm run test:packaging
cargo test --manifest-path src-tauri/Cargo.toml --lib
node scripts/test-apache-overrides.mjs --legacy
node scripts/test-apache-overrides.mjs
```

App version 0.1.22 must match package.json, src-tauri/Cargo.toml and src-tauri/tauri.conf.json. Keep the root package version in package-lock.json and the app package in Cargo.lock synchronized. Historical dependency versions are not app versions.

## Build and finalize

The build stages phpMyAdmin from the unchanged upstream source using `packaging/phpmyadmin-policy.json`. The packages ship `packaging/phpmyadmin-runtime`, not the source directory. Review `packaging/phpmyadmin-report.json` for excluded files and retained hashes. Existing customized files are preserved by hash-checked upgrade cleanup. Test a fresh install and an upgrade before publishing; build success does not qualify the packages by itself.

```bash
npx tauri build --bundles deb rpm
```

This produces the `.deb` and `.rpm` under `src-tauri/target/release/bundle/`. Verify the artifacts: matching version metadata, and install each one in a clean environment before publishing.

For the Arch package, build from a source archive of the tagged commit:

```bash
git archive --prefix=linuxdevstackbox/ -o linuxdevstackbox-0.1.22.tar.gz HEAD
cd packaging/arch && makepkg -f
```

Compute and record SHA-256 checksums for every artifact you intend to upload. Never relabel a previous build's hashes.

## Package acceptance

Test the actual generated packages using [Testing](./testing). Record results in docs/RELEASE-VALIDATION.md. Verify the real Laravel site on HTTP and HTTPS after upgrading and restarting Apache; synthetic rewrite tests alone do not qualify that site. Verify the first-launch flow: user data roots are created under the XDG directories, phpMyAdmin is cloned into the data root, and the only elevated prompts are the two `pkexec` operations.

## Publish after acceptance

```bash
gh release create v0.1.22 --verify-tag --title "LinuxDevStackBox v0.1.22" --notes-file "release/notes-v0.1.22.md" \
  "src-tauri/target/release/bundle/deb/<deb artifact>" \
  "src-tauri/target/release/bundle/rpm/<rpm artifact>" \
  "packaging/arch/<arch package>" \
  "latest.json"
```

Create and push the reviewed v0.1.22 tag before the publish command. Stable releases must not be marked prerelease. Publish `latest.json` with the release so the in-app update check (check-only) detects the new version and directs users to upgrade through their package manager. Verify updates from v0.1.21, then publish the website with its app-doc source pinned to the same release. Keep download URLs, hashes and sizes sourced from the published GitHub assets.
