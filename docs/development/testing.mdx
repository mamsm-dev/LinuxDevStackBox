# Testing LinuxDevStackBox

Automated checks cover parts of the frontend and Rust backend. They do not replace testing the resolved distribution services and packages on real Linux systems.

## Automated checks

From the repository root, run:

```bash
npm test
npm run check:ci
npm run test:packaging
cargo test --manifest-path src-tauri/Cargo.toml --lib
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

- `npm test` runs Vitest (16 test files).
- `check:ci` also runs `tsc --noEmit` and documentation validation.
- `test:packaging` runs `node --test scripts/stage-phpmyadmin.check.mjs` against the staged phpMyAdmin payload.
- `cargo test --lib` runs the Rust unit tests (59 tests). Clippy must stay clean with `-D warnings`.

CI (`.github/workflows/check.yml`) runs `npm ci`, `npm run check:ci`, `npm run build`, `cargo test --lib` and `cargo clippy -D warnings` on ubuntu-latest.

## Apache override regression

Run `node scripts/test-apache-overrides.mjs --legacy` to reproduce the original parent .htaccess error and `node scripts/test-apache-overrides.mjs` to verify the fix. These tests use disposable files and a loopback-only Apache instance, covering a path with spaces, public rewrites, static files and inaccessible private parent files. They do not restart the installed server. Temporary fixture paths are printed for inspection.

## Release checklist

Test the actual packages attached to the release in a clean environment for each supported distro family (Arch, Debian, Fedora):

- Verify the downloaded package against its published checksum, where provided.
- Test first installation with the system package manager, launch, and the desktop entry.
- Test an upgrade with backed-up projects and databases. Verify projects, configuration, and database contents survive.
- Start and stop Apache and MySQL/MariaDB; verify localhost and phpMyAdmin respond while running.
- Check PHP status, extension toggling, and terminal output.
- Test configuration editing, backups, and restoration.
- Import an XAMPP `htdocs` folder (`/opt/lampp`); confirm duplicate path spellings appear only once, existing destination files remain intact, and copied files load.
- Export and import databases separately; the XAMPP import action copies project files only.
- Exercise occupied ports and missing binaries; errors should be actionable without crashing.
- Check English and Hindi, both themes, keyboard navigation, and persistence after restart.
- Verify the `pkexec` (Polkit) prompts for `/etc/hosts` edits and local CA trust are the only elevated operations.
- Check uninstall behavior in a disposable environment, including whether user data under the XDG directories is preserved.

## Paths to verify

| Environment | Example | Verify |
| --- | --- | --- |
| Config root | `~/.config/linuxdevstackbox` | `httpd.conf`, `my.cnf`, `php.ini`, `vhosts.json` and `https/` are generated and editable |
| Data root | `~/.local/share/linuxdevstackbox` | `logs/`, `mysql-data/`, `www/`, `backups/` and the phpMyAdmin copy resolve |
| Overridden data root | `LINUXDEVSTACKBOX_DATA_DIR=/tmp/dsb-test` | Both roots relocate together |
| Development checkout | `/home/<user>/Projects/LinuxDevStackBox` | Development resource paths (staged phpMyAdmin, config templates) resolve |

## Remaining coverage

Manual verification is still required for real service processes, package upgrades, long-running resource use, simultaneous operations, and supported distributions. Add a regression test when practical and retain a manual reproduction for behavior that depends on the installed environment.
