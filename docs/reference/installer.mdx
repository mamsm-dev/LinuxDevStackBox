# Packaging and updates

LinuxDevStackBox ships as Linux packages for the Arch, Debian, and Fedora families. Use GitHub Releases to check which assets are available for a particular version. This page describes package contents, how user data is kept separate from package-managed files, and how update checks work.

## Packages

| Family | Package | Built with | Server dependencies declared |
| --- | --- | --- | --- |
| Debian | `.deb` | Tauri bundler (`deb` target) | `apache2`, `mariadb-server`, `php`, `php-cgi`, `libnss3-tools`, `openssl`, `policykit-1` |
| Fedora family | `.rpm` | Tauri bundler (`rpm` target) | `httpd`, `mariadb-server`, `php`, `php-cgi`, `openssl`, `polkit` |
| Arch | PKGBUILD | `makepkg -f` from `packaging/arch/PKGBUILD` | `apache`, `mariadb`, `mariadb-clients`, `php`, `php-cgi`, `openssl` (`polkit` optional) |

The server dependencies are hard runtime requirements: LinuxDevStackBox does not bundle Apache, MySQL/MariaDB, PHP, or openssl. It resolves them from the distribution packages at runtime.

Download: [devstackbox.com/download](https://www.devstackbox.com/download)

## Package layout

All packages install the same files:

```
/usr/bin/linuxdevstackbox                        application binary
/usr/lib/linuxdevstackbox/phpmyadmin/            read-only phpMyAdmin runtime payload
/usr/share/applications/com.mam.linuxdevstackbox.desktop   desktop entry (Arch package)
/usr/share/icons/hicolor/<size>/apps/linuxdevstackbox.png  hicolor icons (Arch package)
```

The `.deb` and `.rpm` register their dependencies and desktop integration through the Tauri bundler; the Arch package installs the binary, phpMyAdmin payload, desktop entry, icons and license explicitly.

## App vs data directory separation

LinuxDevStackBox separates **package-managed files** from **user data** so package installs, upgrades and removals never touch user state; always back up projects and databases before an upgrade. See [ADR 006](../development/adr/006-app-data-separation) for the full decision record.

**Package-managed files** (replaced by package upgrades):

```
/usr/bin/linuxdevstackbox
/usr/lib/linuxdevstackbox/
```

**Config root** (generated, user-editable; never touched by packages):

```
$XDG_CONFIG_HOME/linuxdevstackbox/      (default ~/.config/linuxdevstackbox)
  httpd.conf        generated Apache config
  my.cnf            generated MySQL config
  php.ini           generated PHP config
  vhosts.json       virtual host records
  https/            local CA and certificates
  mysql-root.json   MySQL root credentials (0600)
```

**Data root** (mutable runtime data; never touched by packages):

```
$XDG_DATA_HOME/linuxdevstackbox/        (default ~/.local/share/linuxdevstackbox)
  www/              project web root
  mysql-data/       MySQL data directory
  logs/             service logs
  backups/          full backups created in-app
  config-backups/   automatic config backups
  phpmyadmin/       writable phpMyAdmin copy (cloned on first run)
  cgi-bin/          staged php-cgi symlink
```

Override both roots together with the `LINUXDEVSTACKBOX_DATA_DIR` environment variable if needed (see [Environment](../advanced/environment)).

Apache serves localhost from the data root's `www` and connected projects from their selected document roots. On first run the app clones the read-only phpMyAdmin payload from `/usr/lib/linuxdevstackbox/phpmyadmin` into the data root, because `config.inc.php` must be writable.

## Update check (shipped)

The app checks GitHub Releases for new versions (an **Auto-check updates** preference exists under Settings → Updates):

- Checks on launch and on a bounded interval; a header indicator appears when a newer version exists
- Manual **Check for updates** on the About page is always available

The updater is **check-only**: when a newer version is detected, the app opens the GitHub release page and instructs the user to upgrade through their package manager (`apt`, `dnf`/`yum`, or `pacman`). Tauri self-update only supports AppImage, which is not a deliverable, so the app never downloads or replaces itself.

**Update check endpoint** (used by `check_app_update`):

`https://github.com/mamsm-dev/LinuxDevStackBox/releases/latest/download/latest.json`

Publishing steps, including publishing `latest.json` with a release, are in [Release process](../development/release-process).

## Uninstall

Remove the package with your package manager (`apt remove`, `dnf remove`, or `pacman -R`). Package removal never deletes the XDG config and data roots; remove them manually if you do not want to keep projects, databases, logs and configuration for a future reinstall.
