## What is LinuxDevStackBox?

LinuxDevStackBox is a free XAMPP alternative for Linux. It manages Apache, MySQL/MariaDB, phpMyAdmin, and PHP as a local development stack. Apache, the database server, and PHP come from your distribution's packages; the app starts, stops and configures them for you.

## Which distributions are supported?

Arch (and derivatives), Debian (and derivatives), and Fedora (and derivatives). The app detects your package family and prints the matching install command when a required binary is missing.

## Which PHP versions are included?

LinuxDevStackBox uses the single PHP runtime installed by your distribution (minimum supported version 8.2). There is no bundled PHP, no version download, and no version switching. Upgrading PHP means upgrading your distribution's `php` package; the app then reports the new version.

## Why does Laravel return an Apache 500 error?

Check the exact Apache log entry. If it names a parent .htaccess with `<IfModule not allowed here`, see the v0.1.17 directory-override fix in [Projects](getting-started/projects). Choose public/ as Laravel's document root. Other 500 errors require their own diagnosis.

## Do updates preserve my php.ini changes?

The editor uses a persistent user copy at `~/.config/linuxdevstackbox/php.ini`. Custom upload, memory and timeout limits are preserved; app-managed runtime paths and error/log settings may be normalized. See [Configuration](reference/configuration).

## Is LinuxDevStackBox free?

Yes. LinuxDevStackBox is MIT-licensed open source. There is no paid tier.

## Where does LinuxDevStackBox install?

LinuxDevStackBox follows the XDG Base Directory Specification:

- Config lives in `~/.config/linuxdevstackbox` (`httpd.conf`, `my.cnf`, `php.ini`, `vhosts.json`, HTTPS certificates).
- Data lives in `~/.local/share/linuxdevstackbox` (`logs/`, `mysql-data/`, `www/`, `backups/`, and the writable `phpmyadmin/` copy).

Both locations can be redirected with the `LINUXDEVSTACKBOX_DATA_DIR` environment variable.

## Must projects live in www?

No. Connect an accessible local folder in Projects without moving files. New folders use `~/.local/share/linuxdevstackbox/www` by default. Open connected sites through their configured hostnames. Full backups do not include external project file contents; back them up separately.

## Can I move projects from XAMPP?

Yes. Connect an existing project folder from **Projects** to keep files where they are, or use **Settings → Import from XAMPP** to copy `htdocs` from `/opt/lampp` into LinuxDevStackBox `www`. Export databases from XAMPP phpMyAdmin and import them in LinuxDevStackBox if needed.

## Does LinuxDevStackBox collect telemetry?

No. LinuxDevStackBox does not collect usage data or phone home. See the [Privacy Policy](/privacy).

## How do I report a bug?

Open a [GitHub Issue](https://github.com/mamsm-dev/LinuxDevStackBox/issues) or start a [Discussion](https://github.com/mamsm-dev/LinuxDevStackBox/discussions).

## How do I report a security issue?

Email **hello@devstackbox.com**. Do not open public issues for vulnerabilities. See [Security](/security).

## Can each project use a different PHP version?

No. There is one system PHP runtime, and every website and terminal session uses it. To run a newer PHP, upgrade your distribution's `php` package. See [Projects, PHP & HTTPS](getting-started/projects).

## Can a trusted HTTPS site return 404?

Yes. A certificate verifies the connection, not application routes or files. Check the document root and entry file in project details.

## Why does my browser or package manager warn about the package?

LinuxDevStackBox packages are built and published as an open-source project without a commercial code-signing certificate. That is expected.

**What to do:** Download packages only from the [official GitHub release](https://github.com/mamsm-dev/LinuxDevStackBox/releases/latest) and install them with your package manager (`sudo pacman -U`, `sudo apt install ./...`, `sudo dnf install ./...`), which performs its own package integrity checks. Compare the package with the hash on the release page if you want extra assurance.
